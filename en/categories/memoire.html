Embedded Memory — RAM, Flash & MRAM

An embedded memory does one thing: store data or code. That's it. What differentiates products is what it stores (volatile or non-volatile), how it connects (on-board or off-board) and what environment it must survive (radiation, temperature, vibration). The rest — throughput, capacity, endurance — are parameters to optimize per application.

Architecture

On-board or off-board?

The first question to ask is not "what capacity?" but "where does the memory go?" Memory soldered directly onto the OBC or PDU board provides compactness and mechanical reliability. Off-board mass storage allows capacity to be expanded in operation and the module to be replaced without touching the main board.

Memory types

Volatile or non-volatile — which to choose?

The first criterion is simple: must the data survive a power cut? From there, each technology addresses a specific trade-off between speed, capacity, endurance and cost.

⚡
SRAM — the fastest
Volatile. Random access in nanoseconds, no refresh time, robust to radiation (no trapped-charge bit-flip). Used as CPU cache, real-time working memory and scratchpad in space OBCs. Expensive and low density.
🌊
DRAM / SDRAM / LPDDR — high density
Volatile. High density (up to 64 GB per module), good bandwidth, but requires periodic refresh and an EDAC controller in radiation environments. Main memory for industrial SBCs, automotive SoCs and high-performance OBCs. Sensitive to SEUs in orbit without EDAC.
🔷
NOR Flash — immutable code
Non-volatile. Fast random read (XIP — eXecute In Place direct code execution), slow sector-by-sector write. Moderate endurance (~100k write cycles). Stores bootloader, firmware and configuration parameters. Standard in simple embedded systems.
📦
NAND Flash — mass storage
Non-volatile. High density and low cost, fast sequential read, but no direct random access — requires an FTL controller. Endurance varies by type (SLC > MLC > TLC > QLC). Mass storage for mission data, logs, images. Basis of eMMC, UFS and embedded SSDs.
🧲
MRAM — the versatile
Non-volatile. Combines SRAM advantages (speed, near-infinite endurance) with Flash (non-volatility). Naturally radiation-resistant — no trapped charge. Reference technology for critical space memories (configuration memory, housekeeping tables). Still costly but increasing density.
🔑
EEPROM — configuration storage
Non-volatile. Low capacity, byte-by-byte write, very high endurance (1M cycles). Simple interface (I²C, SPI). Stores serial numbers, calibration keys, persistent configuration. Present on virtually all embedded systems.
💿
eMMC / UFS / NVMe SSD — mass storage
Non-volatile. Integrated mass storage (soldered eMMC, UFS) or off-board (NVMe SSD, SATA). The FTL controller manages wear-leveling and error correction. File system for embedded Linux, large mission data storage, flight recorders. Available in industrial (−40/+85 °C) and space (rad-hard) grades.

Data protection

EDAC, scrubbing — protecting bits

In radiation environments or safety-critical systems, stored data can be corrupted by external events. Two complementary mechanisms provide protection.

🔍
EDAC — Error Detection And Correction
Error-correcting code (typically Hamming SEC-DED) added to stored data. Detects 2-bit errors and corrects 1-bit errors on the fly, without system interruption. Implemented in the OBC's memory controller or directly in the memory component. Standard on all qualified space OBCs.
🔄
Scrubbing — periodic cleanup
Software or hardware task that periodically reads all memory, corrects errors detected by EDAC, and rewrites the corrected data. Without scrubbing, accumulated SEUs can exceed the correction capacity. Scrubbing cadence calculated per expected radiation flux (LEO vs GEO vs interplanetary orbit).
🪞
Mirroring & redundancy
Duplication of critical memory across two independent banks. If one bank is corrupted beyond what EDAC can correct, the mirror bank takes over. Used for FPGA configuration memory and critical housekeeping tables in satellites. Cost: doubling the memory volume.
Application domains

Same function, different constraints

The basic need — storing bits — doesn't change. It's the environmental and certification constraints that determine which technology, grade and qualification are required.

Space — radiation resistance above all

Satellite · CubeSat · Launcher · Probe
  • Rad-hard SRAM as working memory — EDAC mandatory
  • MRAM or rad-hard NOR Flash for firmware and configuration
  • Cadenced scrubbing on all volatile memories
  • TID tolerance ≥ 30 krad (LEO) to 300 krad (GEO, interplanetary)
  • SEE (SEU, SEL, SEFI) qualified per ECSS-Q-ST-60-15
  • Vibration and thermal-vacuum cycle qualification
  • 10–15 year availability guaranteed by manufacturer
